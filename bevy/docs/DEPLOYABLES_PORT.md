# Original deployable bodies in Bevy

The native `deployables` plugin consumes the original catalog and accepted
`state.deployables` replicas. It creates the ordinary `DeployableReplicaView`
branch with the source mesh, material, pose and fixed collision box. It never
spawns an object from an unaccepted placement intent or changes inventory.

Source contracts:

- `game/Deployable.cs:BuildMesh/Spawn`: `MeshBasis` rotates the original mesh
  AABB's eight corners; that AABB supplies the offset box and ground lift.
  It is deliberately not a tighter bound over rotated triangle vertices.
- `game/DeployableDef.cs`: original YXZ mesh rotation, yaw then X stand-up,
  nearest palette, double-sided roughness1 material, gray procedural boxes.
  Battery label remains a child in the mesh's authored frame. Existing
  `UG_DEPLOYROT`, `UG_BATROT`, `UG_LBLP` and `UG_LBLR` tuning is retained.
- `game/Barricade.cs` and `BarricadePlacer.cs`: ceiling standoff0.005m,
  wall standoff `min(Offset,0.1)`, container half-depth plus0.01m; accepted
  `MountUp` selects the source upward-facing container pose. The JSON view now
  retains that existing wire bit. No wire IDs or game rules changed.
- Replicas diff by accepted NetId. Missing replicas and new session epochs
  retire their scene hierarchy. Local-frame pose changes update existing roots.
  The host exports the same transformed box under `deployable:<id>` and marks
  its actual deployable ID for combat and station self-exclusion. Geometry
  revision changes force upload again after terrain replacement. Remote UDP
  clients render bodies but never upload authority geometry.

Specialized fixture, fluid, storage-appliance and wind-turbine branches remain
separate work. Ordinary bodies now provide source camera focus, basic health/fuel
readouts, hold-F pickup and short generator toggle intents. The foundation does
not yet complete power ports/networks, battery/load/time readouts, lights,
fire/wreck presentation, configurable-device panels, placement ghosts, window
snapping, item pipes, or those specialized bodies. The fuel-free source switch
now accepts the existing toggle and gates solver conduction, with its original
red/green native state indicator; the foundation and remaining utility scope are
tracked in [POWER_PORT.md](POWER_PORT.md).
Retaining the original backend rules does not make those native flows playable.

## Focus and accepted pickup

The active owner camera casts the original 2.6m ray against world and vehicle
bodies, excluding its own body and sensors. An ordinary deployed ancestor
offers the shared interaction focus; the winning source body supplies
`info_billboard::FocusedInfo`, rather than a second HUD hint. UI capture, death,
seating, focus/reach loss and fire cancel a hold. Input uses the existing
per-window ordered key/mouse batch and rebound physical Interact binding. A new
press during event-time free-look does not start a hold.

The original hold lasts one simulation second, with a 20% progress deadzone.
Release cancels progress; a short generator/switch tap sends the existing
toggle intent. Completion sends one existing pickup intent and clears the
gesture without locally removing the body or granting an item. Only the
accepted replica and owner inventory echo perform those changes. Generator
warmup/cooldown gates quick toggles with the source 1.3s/1.1s cosmetic ramps;
singleplayer pause freezes these ramps. This adapter does not simulate power
production or fuel drain.

Nine focused native tests pass on `native-pickup-reviewed-tests`, including an
actual UDP owner exercising the production focus/hold systems: occlusion,
reach cancellation, event-time free-look, no optimistic removal, accepted
retirement and exactly one refund. The full PEI main executable
`native-pickup-shader-fixed-main` uses immutable protocol73 backend
`finite-respawn-v73-second`. Actual OS input produced the opened captures
`bevy-pickup-final-{reloaded,progress,cancelled,hold-continued,accepted,inventory}`:
visible hint, 20%, cancelled with body retained, 70%, accepted body removal and
one Workbench1916 in Inventory. Pause → Quit exits0. Under software Vulkan the
fixed-fps20 harness advances slowly in wall time; holds were measured in game
frames. This proves the ordinary pickup journey, not remaining utility flows.

Numeric references are generated by actual Godot4.6 AABB/Basis operations in
`bevy/tools/deployable_source_reference.gd`. Its three arguments are a catalog
JSON dump (`catalog.result.deployables`), content root and output JSON. The
checked-in `src/deployables/source-reference.json` contains141 floor, wall,
ceiling and container-top cases over every ordinary definition. It is a numeric
engine reference, with no screenshot golden gate.

Verification is recorded in `PROGRESS.md`; playable captures live under
`bevy/artifacts/bevy-deployable-*`. The PEI Workbench was placed through the
accepted command and restored from a task-owned save. Shipping content remains
unchanged; the prior station experiment's isolated recipe file is used only by
that test session.
