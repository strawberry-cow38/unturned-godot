# Nearby owner inventory

The hybrid client now has a dedicated accepted Nearby projection. Public world-item snapshots still carry their original lightweight fields; they are not treated as an inventory or used to invent attachment, cartridge, fluid or instance state.

## Source and authority

`PlayerController.ScanNearbyItems` reads the actual active camera, tests distance strictly below four metres, and scans the world-item scene group in insertion order. `WorldItem.HasLineOfSightFrom` accepts any clear ray to the model hitbox centre or eight padded corners using source world bit 0. `Items.tryAddItem` supplies the original 6×6 packing, stacking and currency normalization. The bridge resolves current original item-model bounds and the existing native dropped/stuck pose. This includes native look-to's finite collinear fallback. Native ordinary dropped yaw remains its pre-existing deterministic net-ID pose, rather than Godot's random tumble.

The server applies those operations to private clones. Each displayed row retains every contributing live world ID, original item ID, and exact instance token. Opening the dashboard never mutates loot. Scene insertion order is tracked independently of net IDs. Only contributions that fitted the opening scan are retained; refresh repacks their remaining admitted amounts and current accepted fields. Newly spawned items require reopening. This refresh/repacking policy is an adapter choice, not a claim of identical source cell retention during concurrent changes.

Every Take or Store rechecks the live owner, accepted camera envelope, strict radius, current LOS, scan/revision/root cell, complete original item bytes, and all contributor tokens before the original destination add operation. Store also requires the owner's current crate, viewer membership, current access/reach, exact destination page and backing dimensions. Only the amount actually accepted is debited from the original world sources; partial currency stacks and change conserve value. Public world-item change/removal and all affected container viewers are refreshed. Server AREA remains empty.

## Protocol 76

Append-only Command 86 carries Open, Close or Transfer with an owner request ID, bounded eye and exact scan/row/world identity. Event 63 is owner-only and carries a revision, accepted tick, result, and bounded full-item rows with contribution identities. It reuses the jar codec and explicitly appends its missing/raw fields, including nullable cartridge strings and preserved/fuel/fluid values. Existing System 7/System 8 and legacy command encodings are unchanged. Published version 75 peers are rejected by the version handshake.

Rows are limited to 36 and total contributions to 4096; strings are bounded before allocation. Decode is atomic. Duplicate/ambiguous identities, overlap, malformed dimensions, invalid numbers and truncated packets are rejected. Exact request replay cannot debit twice; disconnect discards scans and replay state. Legacy grid commands cannot target AREA.

## Native scope

The production Inventory controller requests Nearby once per opening from the completed camera, draws only the received rows, and dispatches exact accepted addresses. Context Take, context Store and Ctrl-grab are supported. Ctrl-grab always targets the owner's inventory; Store uses the currently accepted source container page. No optimistic inventory edits or automatic weapon equip occur.

## Protocol 77 ground operations

The original reference's AREA page is a client-local pack of world items, so its gestures either act on the world item itself, refuse, or produce local-only state. Each is ported deliberately:

| Gesture on a ground row | Godot reference | Port |
| --- | --- | --- |
| RMB one-unit carry, split strip drag-out | `DoSplitTo` → `OnSplitItem` named cell (merge same ID up to stack size, else empty footprint; never the whole stack) | Command 87 `Split`, same cell rule against the exact row. Two documented tightenings that `OnSplitItem` lacks: the `TryDrag` holster rule (hand slots at (0,0) rot 0), and no merge onto a magazine (its amount is rounds, as `TryDrag` already guards) |
| LMB whole drag to a cell, with R/Space rotation | `TryDrag` refuses AREA endpoints (snaps home); its comment routes pickups through their own path | Command 87 `Place`: an **adapter extension** requested for this checkpoint, using `TryDrag`'s own cross-page rules: holster `CanOccupyPage`, rotation-aware `checkSpaceEmpty`, hand slots at (0,0) rot 0, same-ID merge up to stack size (magazines excluded) with the remainder left on the ground. Any other occupant would be a swap and is refused: a ground row cannot receive it. Placing into a hand slot only holsters; nothing is equipped, so the source's "no equipping off the floor" paperdoll rule still holds |
| Context Empty on a fuel container | `EmptyFuelSelected` zeroes the selected jar, i.e. the world item itself | Command 87 `EmptyFuel` on the exact single-contributor world item |
| Context Unload; round dragged onto a magazine | `UnloadSelected` / `TryStartLoad`, timed `StepMagOp` with `FindStack` over every page, AREA included | Command 88, one original `MagRules` round per request |
| Equip/Hold, paperdoll, worn slot, Drop, right-half drop, drags onto AREA | Paperdoll refused and tested (`ContainerEquipTests`); right-half drop and `TryDrag` exclude AREA; context Equip/Hold/Drop only created local hand state or a second world node over a ground item | Refused with the existing notice; nothing is sent |
| Salvage | Offered **only on owned pages** (`OpenSelection`: "OWN PAGES ONLY") | Not offered for AREA or viewed pages |

Command 87 carries the same exact identity as Transfer plus an operation, amount and named destination. `CrateId` zero admits only owned pages; a nonzero ID admits only a page of the currently viewed container, with the same open-crate, viewer, access and backing-dimension checks as Store. Every operation reruns the full Take admission before mutating: live alive owner, accepted camera envelope, current scan/revision, row root and first contributor, every contributor's live ID/token/full bytes, strict range and LOS. Only the accepted amount is debited from contributors in source order, including the existing currency normalization. The result is a new Event 63 revision; `Transferred` means the operation applied. Commands 86 and 87 share one monotonic per-owner ledger: exact replay resends the stored revision and never re-applies.

Command 88 names the magazine and the round as either a received ground row (world ID, token, root) or the existing scoped owned/container address; at least one part is ground, and unload names only the expected loose-round ID. A ground part is admitted by the current scan plus its exact first-contributor identity, wherever the latest repaint put it, followed by the full Take recheck against the newest picture (every contributor's live token and full bytes, camera, range, LOS). The revision is deliberately not required here: source magazine jobs run concurrently and each accepted round repaints the picture, so an exact revision let one job, or anyone's nearby pickup, cancel another mid-batch (independent review finding, now a regression test). The live world item behind an admitted row is mutated, never the display clone. Unload adds the round to the owner's bag before decrementing; a ground round stack is debited one round from its first contributor. Results reuse Event 60 and the same per-owner ledger as commands 81/85. The owner's Nearby picture is republished in the same tick, and the native job waits for both the owner snapshot and that Nearby tick before choosing the next source stack. Ground jobs are keyed by world identity rather than cell. A request with no reply for 10 s retires its job (an adapter bound: a request the bridge did not queue would otherwise spin the wheel forever, and a retry would be a stale ID on the shared ledger). A non-stacking, non-currency world item is now projected at its live amount: a loaded ground magazine grows rather than staying capped at its opening quota, which would otherwise leave a second magazine body behind on Take.

Splitting a loaded magazine into an empty cell creates a second magazine body with the split rounds. That is the source `OnSplitItem` rule the owned dashboard already ports; it is retained for ground rows rather than silently changed, and no new test depends on it. The owned `OnSplitItem` still lacks the holster rule and the magazine merge guard; that pre-existing owned-page gap is outside this checkpoint.
