# Dropped item visuals

`entities/items.rs` ports `WorldItem.GetModel`, `MeshForAmount`, and `BuildReplicaVisual`; `entities::sync_world_items` consumes accepted world-item replicas. Dropped models come from `content/items/items_manifest.json`, independently of the held-model catalog. This restores real folded-shirt, pants, hat and other dropped models that previously disappeared when the held mesh field was null.

The original manifest supplies mesh, texture, flat color, source bounds, multi-round triangle cutoffs and material flags. Textures have generated mip chains with nearest filtering. Textured items retain source roughness .8, or .3 for the source `metal` flag (metallic remains0 intentionally). Flat-color meshes use .7 roughness. Missing models, including unknown catalog IDs, retain the source .24 m rarity-colored cube at .55 roughness. Source +90° X and deterministic NetId yaw are preserved.

Stack amounts use the original inclusive band rule and actual OBJ triangle prefixes; a change updates the existing entity and reuses cached prefix meshes. Pickup selection now traces the transformed original bounds enlarged15%, including off-center and wide clothing shapes. The selector never gives these visual replicas physical collision with players or bullets.

Four native tests load actual clothing and ammunition assets and verify real model/mipmap/material/focus behavior, original lower band boundaries, accepted amount changes without entity replacement, cached prefix reuse, authoritative removal, and visible/focusable rarity fallback for missing models/catalog entries. Managed profile tests also verify actual rarity/stack metadata. Live clothing drop/pickup evidence will be recorded with the inventory journey.

Remaining source behavior is explicit: the original focus silhouette and floating rarity/name label are not implemented. The host-side dropped item's gravity/toss/settle body and accepted pose publication remain separate work; a replica does not simulate itself. Original `WorldItemReplicaView.BuildItemPuppet` does not mount gun attachments (the physical `WorldItem` does); this slice preserves that boundary and does not invent attachment state absent from the replica schema. Original per-item view-cone/occlusion culling also remains pending.

The depth-prepass target is the actual Godot **4.6-stable** renderer, rather than the stronger self-overlap claim in the `WorldItem.cs` comment. Its [forward clustered shader](https://github.com/godotengine/godot/blob/4.6-stable/servers/rendering/renderer_rd/shaders/forward_clustered/scene_forward_clustered.glsl#L1416) discards fragments below `opaque_prepass_threshold`; [the main scene sets 0.99](https://github.com/godotengine/godot/blob/4.6-stable/servers/rendering/renderer_rd/forward_clustered/render_forward_clustered.cpp#L1791), while [shadow rendering sets 0.1](https://github.com/godotengine/godot/blob/4.6-stable/servers/rendering/renderer_rd/forward_clustered/render_forward_clustered.cpp#L2770). The manifest currently marks six items translucent: Drinking Glass9301 has constant alpha112/255, Ice9347 has constant alpha204/255, and Pens9317/9318/9319/9343 contain alpha51..255. Thus glass/ice contribute no main depth-prepass pixels; the pens' opaque pixels do. All six have pixels above the shadow threshold. The native adapter reproduces these thresholds and subsequent alpha blending; it does not force depth writes for every transparent surface.

## Source alpha-depth material adapter

Bevy0.20's `specialize_prepass_material_meshes` explicitly skips `AlphaMode::Blend`, and `MaterialPipelineKey` does not carry a general shadow-pass discriminator (both main depth and point-light shadows use the depth-prepass key). Guessing the pass from orthographic projection would silently fail for point lights. `entities/items/material.rs` uses `MaterialExtension` controls without an engine fork:

1. Keep the original PBR alpha-blended color mesh, with `NotShadowCaster`. Its transparent color pass keeps depth writes disabled, matching Godot4.6 `SceneShaderForwardClustered`'s `DEPTH_DRAW_OPAQUE` behavior.
2. Add a colocated companion with `StandardMaterial::alpha_mode = Mask(0.99)` and a depth-only extension. Disable color writes in the main pass, preserve the depth prepass, and return `enable_shadows=false`. Thus the opaque texels establish depth before transparent color, without double-coloring them.
3. Add a shadow companion with `Mask(0.1)`, `enable_prepass=false`, and shadows enabled. Its main-pass specialization disables both color and depth writes; its shadow pipeline retains alpha-tested depth writes. Distinguish a prepass pipeline by the actual `PREPASS_PIPELINE` shader definition, not the camera projection. Both companion materials share the original texture and sampler. They need no collider or focus target.

The `AlphaDepth` marker synchronizes all three mesh handles on amount-prefix changes. Pose/rebase follows one common parent, and despawn retires the complete group. Source culling, render layers, texture sampler and optional skinning are shared by the companions. Late-loaded materials retry; changed source materials invalidate the cached companions. Removing the marker or replacing an accepted item with opaque clothing removes both companions. Specialization visits every present optional color target, including an empty target list for shadows. The world/HDR reviewer found no ordering conflict: world postprocessing consumes the completed scene color/depth.

Eight focused content/material/lifecycle tests pass, including actual material specialization, optional/empty color targets, late material loading, all six original translucent textures, accepted replacement and parent cleanup. The complete native suite passes288 tests at this checkpoint. Two independent reviews found no blocking pass or lifetime issue.

The actual Godot4.6.2 and Bevy threshold fixtures were rendered with Vulkan/lavapipe, opened and compared. Each fixture deliberately submits front green triangles before opaque red rear triangles within one mesh. Blend-only loses all front triangles to later color; the source adapter preserves front pixels only at alpha253/255 and255/255. The separate shadow scene starts casting at26/255. These byte boundaries match the original0.99 main/0.1 shadow thresholds. Actual glass9301, pen9317 and ice9347 were also rendered overlapping from two angles with a shadow receiver; transparency, the original opaque pen pixels and shadows are visible, with no shader validation errors. These isolate material behavior rather than asserting whole-game lighting parity.

Inspected evidence under `bevy/artifacts/`:

- `godot-alpha-depth-threshold.png` and `bevy-alpha-depth-threshold.png`: original/native pass behavior.
- `bevy-alpha-depth-shadow.png`: separate shadow cutoff.
- `bevy-alpha-depth-real-front.png` and `bevy-alpha-depth-real-side.png`: original asset overlap and shadows.

Reproduce the native fixture with `cargo run --example alpha_depth -- --shot /tmp/alpha.png`; add `--shadow`, or `--real` and optionally `--side`. On a displayless machine use `env -u WAYLAND_DISPLAY VK_ICD_FILENAMES=/usr/share/vulkan/icd.d/lvp_icd.json xvfb-run -a` around the executable. `bevy/tools/alpha_depth_reference.gd` is the matching original-engine fixture; run with the real Vulkan renderer, movie mode and a minimal Godot project, never the dummy headless renderer. This is an inspectable diagnostic, not a visual-golden gate.
